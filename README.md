# 项目拷问官

面向大厂技术岗候选人的 AI 项目深挖面试官。它不做泛泛的面试陪聊，而是围绕用户简历里的一段项目经历，像真人技术面试官一样连续追问：你到底做了什么、为什么这么做、怎么验证有效、哪里失败过、能不能落地到真实企业场景。

## 项目简介

目标用户是准备技术岗实习、校招或研究生后求职的同学，尤其是简历里有 AI、代码、算法、机器人、后端工程等项目，但担心项目“写得出来、讲不清楚、经不起追问”的人。

核心问题：

> 技术岗候选人的简历项目，能不能扛住真实面试官连续深挖？

项目拷问官的核心闭环是：输入项目经历 -> 生成事实卡 -> 一问一答追问 -> 限时回答 -> 每轮评分 -> 最终复盘报告 -> 历史记录回看。

## 运行方式

项目只保留一种启动方式：

```bash
cd /root/aiic/project-interrogator
python3 server.py
```

启动后访问：

```text
http://服务器IP:8000
```

首次访问后可以直接注册测试账号。注册、登录、历史记录和模拟报告都会保存在本地 SQLite 数据库中。

## 配置方式

所有运行配置集中在 [config.yaml](config.yaml)：

```yaml
server:
  host: 0.0.0.0
  port: 8000

dashscope:
  api_key: "你的阿里百炼 DashScope API Key"
  model: "qwen3.5-122b-a10b"
  url: "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions"
  temperature: 0.35
  timeout_seconds: 45

app:
  max_safety_rounds: 10
  session_ttl_seconds: 1209600
  require_json_output: true
```

目前本地已经配置好了api-key可以直接运行。

其中 `max_safety_rounds` 用来约束一场模拟最多 10 轮内结束，避免 AI 无限追问。

## 技术栈

- 后端：Python 3 标准库 `ThreadingHTTPServer`
- 数据库：SQLite，本地保存用户、会话、消息、模型调用日志和报告
- 前端：原生 HTML / CSS / JavaScript
- 模型服务：阿里 DashScope 兼容 OpenAI Chat Completions 接口
- Prompt 管理：`prompts/` 按任务拆分系统提示词、问题生成、agent 决策和报告生成
- Skill 管理：`skills/` 按能力拆分追问原则、评分 rubric、技术方向和 agent 策略

项目没有引入 npm 或 pip 依赖，便于在短时间内直接部署和复现。

## 核心功能

- 项目事实卡：先把项目拆成技术方向、岗位关键词、缺失证据和高风险追问点。
- 证据链拷问图：围绕“主张、需要证据、风险点”判断项目是否经得住问。
- 行业趋势追问卡：追问成本、可靠性、合规、部署、ROI 和真实企业场景。
- 一问一答模式：每次只问一个核心问题，不一次抛出题目列表。
- 动态压力阶梯：回答扎实就追更深，回答空泛就收窄到代码/数据/指标，回答跑题就直接要求回到本题。
- 回答相关度判断：回答和问题对不上时会压低分数，避免用背稿和专业词堆砌混过去。
- 回答时长评分：同时参考实际耗时和按文本长度估算的口述耗时，超时越多表达效率越低。
- 两种反馈模式：实时反馈适合练习修正，结束后反馈更接近真实面试。
- 历史记录：按用户保存每次模拟、每轮问答、评分、报告和模型调用日志。
- 手动终止：用户可以强行结束面试，并立即生成复盘报告。

## 使用流程

1. 注册或登录账号。
2. 填写技术方向、面试强度、面试官风格、反馈模式、岗位关键词和项目描述。
3. 点击“开始拷问”。
4. 系统生成事实卡，并开始第一轮问题。
5. 用户在建议时长内回答问题。
6. 系统根据回答生成反馈、评分和下一轮追问。
7. 模型判断是否继续、加压、收窄、重问或结束；整场模拟会控制在 10 轮内。
8. 训练结束后进入报告页，查看每轮评分、总分、痛点、改进建议和示例回答。
9. 之后可以从历史记录中回看，也可以开启新的模拟。

## 评分与反馈

候选人每轮都会从六个维度评分：

- 真实性：是否证明自己亲手做过，有明确个人贡献和实现证据。
- 技术深度：是否讲清技术选择、替代方案、边界和失败原因。
- 指标意识：是否讲清数据来源、baseline、指标、实验和失败样本。
- 工程落地：是否考虑部署、性能、稳定性、异常、成本和回退。
- 趋势判断：是否理解行业场景、企业关心的问题和方向发展脉络。
- 表达效率：是否在合理时间内先给结论、再给证据、最后收束。

报告会包含：

- 每轮问题分析
- 每轮回答分析
- 每轮六维评分和本轮平均分
- 最终总分
- 痛点在哪里
- 如何改进
- 更好的完整示例回答
- 下一轮训练重点

系统还会记录工具本身的训练有效性指标：问题相关度、追问深度、诊断准确度、训练增益和复盘价值。

## 产品亮点

1. 不是题库，而是从用户自己的项目材料出发追问。
2. 不是只给模板建议，而是指出证据缺口、跑题和个人贡献风险。
3. 不只问技术细节，也追行业趋势和真实企业落地约束。
4. 不固定轮数，交给 agent 根据回答质量决定继续、收束或结束。
5. 不只评价候选人，也衡量工具本身是否真的帮用户提升。

这些设计是为了让产品相比直接使用 ChatGPT 更适合“项目抗拷问训练”这个窄场景。

## 项目结构

```text
project-interrogator/
  backend/
    ai.py                     # 阿里 DashScope 调用
    auth.py                   # 登录注册和 token 校验
    config.py                 # config.yaml 读取和路径常量
    handler.py                # HTTP 路由处理
    http_utils.py             # JSON 请求/响应工具
    prompts.py                # Prompt 组装和 skill 加载
    storage.py                # SQLite 表、会话、消息和日志
  prompts/
    system.md                 # 全局系统 prompt
    questions.md              # 首轮问题生成 prompt
    agent_step.md             # 面试 agent 决策 prompt
    report.md                 # 最终报告 prompt
  skills/
    core/                     # 通用原则、追问轴、评分 rubric
    tracks/                   # 不同技术方向深挖策略
    agent/                    # 面试 agent 决策策略
  web/
    index.html                # 前端页面
    styles.css                # UI 样式
    js/
      state.js                # 全局状态
      api-auth.js             # API 请求、登录注册和历史列表
      domain.js               # 事实卡、问题生成和反馈归一化
      scoring.js              # 本地评分、时间评分和训练有效性指标
      render.js               # 页面渲染、报告和错误提示
      interview.js            # 一问一答流程、计时、保存和报告生成
      main.js                 # 事件绑定和页面初始化
  examples/                   # 可复制的经典测试案例
  data/                       # 运行时 SQLite 数据库
  config.yaml                 # API key、模型、端口和应用配置
  server.py                   # 唯一启动入口
  Memo.md                     # Product Memo
```

## 测试案例

[examples](examples/README.md) 目录保留了几个经典案例：

- 代码项目 / Code Review Assistant
- 机器学习风控模型
- 后端订单系统
- Robotics 与 VLM 大模型训练

每个案例都包含推荐技术方向、岗位关键词、项目描述、重点追问方向、弱回答和强回答，适合测试系统是否能把问题追深、把分数拉开。

## 数据与隐私

运行数据保存在：

```text
data/interrogator.sqlite3
```

保存内容包括用户账号、密码哈希、面试会话、每轮问答、模型调用日志和最终报告。测试时建议使用脱敏简历或假数据，不要输入真实个人隐私信息。

## MVP 取舍

本项目刻意没有做完整简历解析、公司定制题库和语音视频面试。16 小时内优先把一个最核心的训练闭环做扎实：围绕一个项目持续追问，并给出能复盘、能改进、能二次训练的反馈。
