# 案例 03：秒杀订单后端系统

推荐技术方向：后端 / 工程系统

岗位关键词：高并发、库存一致性、限流、幂等、队列、监控

重点追问方向：核心链路、事务一致性、异常处理、压测指标

## 项目描述

秒杀订单后端系统。项目目标是在高并发场景下支持商品抢购，避免超卖、重复下单和服务雪崩。我负责下单接口、库存预扣、订单创建、幂等控制和基础压测。技术栈包括 Java、Spring Boot、Redis、MySQL、消息队列和 Nginx 限流。核心链路是用户请求先经过限流和登录校验，再用 Redis 做库存预扣和用户维度幂等标记，订单异步写入消息队列，消费者落 MySQL。压测时我记录了 QPS、P95 延迟、库存一致性和失败率。当前方案仍有补偿任务和队列堆积处理不完善的问题。

## 弱回答测试

我用了 Redis 和消息队列，所以可以支持高并发，也能防止超卖。

## 强回答测试

我负责下单链路。请求进入后先做用户登录和活动状态校验，再用 Redis Lua 脚本原子检查库存和用户购买标记，成功后写入预订单消息。消费者落库时用订单唯一键保证幂等。这样做牺牲了一部分实时一致性，换取削峰能力。评估时我看 QPS、P95 延迟、Redis 扣减成功数和 MySQL 最终订单数是否一致。风险是消息队列堆积和消费者失败，所以需要补偿扫描、死信队列和库存回滚机制。
